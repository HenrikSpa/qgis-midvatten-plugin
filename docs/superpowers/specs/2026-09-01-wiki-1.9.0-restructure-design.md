Status: approved design, awaiting implementation plan

## 1. Goal

Ship a wiki that matches plugin 1.9.0 exactly, reads as professional end-user
documentation, and can be kept in sync cheaply: every figure is regenerated by
a script, every menu label is copied from the plugin's action manifest, and
the tutorial dataset exercises the whole 1.9.0 schema.

Decisions already taken (2026-09-01):

| Decision | Choice |
|---|---|
| Version label | **1.9.0** (not "2.0" as in the April draft) |
| Screenshot source | QGIS 4.2.2 on Qt 6.9 in Docker (`qgis/qgis:4.2.2`) |

## 5. Page content rules

### 5.1 Feature section template (all how-to pages)

```
### <Exact menu label>
Menu: Midvatten ▸ <Submenu> ▸ <Label>   Toolbar: yes/no   Shortcut: (F6 only)
**What it does** — 1–3 sentences.
**Requires** — DB connected; selected features in <layer>; active layer <x>; PostGIS-only/SpatiaLite-only.
**Steps** — numbered, each step names a control by its exact caption.
![<figure>](images/1.9.0/<figure>.png)
**Options** — table: Control | Meaning | Default.
**Notes / errors** — message-bar texts the user may see and what to do.
**Data written** — tables/columns touched (links to Database-tables).
```

### 5.2 Style

English, second person, present tense, no marketing. Control captions in
**bold** exactly as in the UI; table and column names in `code`. Every page
opens with one paragraph stating what the page covers. Version callouts only
where behaviour changed in 1.9.0 (`> **Changed in 1.9.0:**`). No "v2.0" anywhere.

### 5.3 Database pages

Generated tables (§7.3) for columns/types/constraints; hand-written purpose
paragraphs. Mermaid ER diagram split in two (observation objects + time series;
quality/geophysics/metadata) to stay legible. Footnote that zz_* links are
soft. Upgrade section states the two real paths and the 1.11.1 version.

## 7. Screenshot pipeline

Location: `tools/screenshots/` in the wiki repo (kept with the docs; it drives
the plugin only through public actions).

### 7.1 Environment

`tools/screenshots/Dockerfile`: `FROM qgis/qgis:4.2.2` + `python3-pyqt6.qtwebengine`,
`xvfb` (present), `pip install pandas`. Plugin mounted read-only at `/plugin`
and symlinked into a scripted profile at `/work/profiles/shot/python/plugins/midvatten`.
Verified 2026-09-01: QGIS 4.2.2 / Qt 6.9.2 / PyQt 6.9.1 starts under
`xvfb-run -a -s "-screen 0 1600x1000x24"`, the plugin loads via
`qgis.utils.loadPlugin/startPlugin`, menu and toolbar appear,
`iface.mainWindow().grab().save()` works. (Plain `QT_QPA_PLATFORM=offscreen` is
refused by the QGIS binary: "non-interactive mode not supported".)

Host QGIS 3.44 (Qt5) is a secondary runner for spot checks only.

### 7.2 Harness

- `shoot.py` (host side, Python): builds the image if needed, runs one container
  per invocation with `--code /work/runner.py`, passes the figure selection via
  `--py-args`. Flags: `--figure NAME` / `--all`, `--dpi {1,2}` (QT_SCALE_FACTOR),
  `--out images/1.9.0/`, `--keep-window` for debugging.
- `runner.py` (inside QGIS): opens `tutorial.sqlite` through the Settings dock,
  loads the project, then for each requested figure imports `scenes/<name>.py`
  and calls `scene(ctx)`; `ctx` exposes `plugin`, `iface`, helpers
  `open_action(action_id)` (uses `plugin._actions_manifest` + `_dispatch`),
  `top_dialog()`, `select_obsids([...])`, `grab(widget, name, margin=8)`,
  `grab_region(widget, child_object_name)`. Crashes in a scene are logged and
  the runner continues; exit code non-zero if any figure failed.
- `manifest.toml`: figure name → scene, widget, caption, page(s) that use it.
  A check script fails if a page references a figure not in the manifest or
  the manifest has a figure no page uses.
- Output: PNG, 1× DPI, dialogs cropped to the widget, map canvas figures at
  1600×1000; file names `images/1.9.0/<page>_<feature>[_<detail>].png`.

### 7.3 Generated content

`tools/gen_reference.py` (runs in the container) writes:
- `_generated/actions.md`: submenu / label / toolbar / requirements per action from the manifest (for copy-into pages and for the label-check script).
- `_generated/schema.md`: tables, columns, PK/FK/unique from `create_db.sql` via the plugin's own `db_defs`, for pasting into Database-tables and Database-constraints.
A `check_labels.py` script greps how-to pages for `### ` headings and fails on any heading not present in `actions.md`.

### 7.4 Figure list (≈45)

Home: hero composite (canvas + tsplot + section + piper). Getting-started: settings
dock, create-DB dialog, loaded layers panel, obs_points form with Screens tab,
tutorial map. Import: CSV import (main, file-load sub-dialog), logger import
(dialog, progress), interlab4 (dialog, Assign obsids), FieldLogger. Export: CSV
dialog, SpatiaLite dialog + progress, FieldLogger export. Edit: calc w level;
LoggerEditor ×5 (overview, Adjust level, Series tab, duplicate banner + resolve
dialog, reference series dock); aveflow. Plots: tsplot, xyplot, stratigraphy,
section ×3 (dialog, plot with screens, TEM), custom plots (+ Fix style files),
piper. Reports: drill report, custom drill report, WQ table, compact WQ (settings
+ output). DB mgmt: PostGIS populate, Settings DB tab schema combo, backup
message. Utilities: strat symbology dialog, list of values, data-domain layers.

## 8. Work phases and parallelism

1. **Repo prep** — merge `wiki/v2.0-update` into master; rename pages, add stubs; global "2.0"→"1.9.0" pass; delete invented sections (§3.1). Outcome: an honest-but-unillustrated wiki.
2. **Environment** — Dockerfile + `shoot.py` skeleton reproducing the verified probe.
3. **Dataset v2** — `build.py` and the zip (depends on 2 for the DB creation step).
4. **Harness + scenes** — `runner.py`, first 5 scenes, then the rest (depends on 3).
5. **Content** — page rewrites per §4/§5 using §3 as checklist and `_generated/*` for labels/schema. Independent of 3–4 except figure references; can run in parallel with them.
6. **Assembly** — sidebar, footer, Home feature grid, legacy hub; run `check_labels.py`, manifest check, a link checker (internal `[[...]]` and relative image paths), image-size check (< 400 KB each).
7. **Ship** — final review, commit on master, push to GitHub wiki; update memory notes.

Phases 3, 4 and 5 are independent enough for subagents (dataset, harness, prose).

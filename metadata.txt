about=The plugin is a toolset that makes QGIS an interface for editing/viewing hydrogeological observational data (drillings, water levels, seismic data etc) stored in a SQLite or PostgreSQL database. NOTE: This plugin requires the Python packages numpy, pandas and matplotlib. These are installed automatically by the qpip helper plugin. When you first install Midvatten, qpip will show a dialog asking to install these packages — click "Install" to proceed. This is a one-time step.

You can inspect the map and attribute tables (e.g. obs_points) while assigning obsids, and the dialog's reload button becomes genuinely useful: create the missing obs_point in QGIS, reload, assign.
          - UX: The interlab4 obsid assignment dialog now keeps typed obsids and skip marks in an in-session draft. Reopening the import after "Save draft" or a cancelled run restores what you already typed, with restored rows marked visibly; auto-matched rows stay out of the draft.
          - Reliability: Saving obsid assignments to the connection table now uses insert-or-ignore, so re-answering an already-stored connection keeps the first answer instead of raising an error.
          - Fix: FieldLogger import no longer opens an empty import window when the file dialog is cancelled.
          - Internal: The interlab4 importer's ask-obsid table construction, imported-report lookup, and assignment-cache read/write are now headless module-level helpers (usable without the GUI, explicit database connection, batched cache writes); the dialog methods delegate to them.
          - Fix: SpatiaLite databases on Windows paths (backslashes) failed to open; the database setting is now saved as JSON, so a path segment like "\336" is no longer misread as an octal escape.
        Version 1.9.0b31:
          - Security: Imported data and shared databases are handled more safely. CSV import validates declared column types before using them, and all generated reports (drill reports, custom drill reports, water quality reports) escape text values, so a malformed or malicious database can no longer inject code when a report is opened in the browser.
          - Security: Generated reports and exported CSV files are written to private per-run temporary folders instead of a fixed shared path.
          - Reliability: The plugin now loads and runs with SpatiaLite databases even when the PostgreSQL driver (psycopg2) is not installed; attempting a PostgreSQL connection then shows a clear message instead of the whole plugin failing to load.
          - UX: Many status and "nothing selected" messages that used to open a dialog now appear in the QGIS message bar, so they no longer interrupt your work; errors show a short message with the full details in the log panel.
          - UX: Export to FieldLogger/FieldForm settings changes now update the open dialog in place instead of asking you to restart it.
          - UX: Lab data (interlab4) import collects parsing problems into a single summary instead of showing one dialog per bad row.
          - Reports: Drill reports, custom drill reports and Piper plots now show a progress dialog with a working Cancel button; the FieldLogger export preview is a resizable, scrollable window.
          - Qt6: Removed a Qt5-only matplotlib backend setting so plots work under Qt6 builds of QGIS.
          - Packaging: Fixed the plugin build script so the published archive no longer includes development files.

        Version 1.9.0b30:
          - LoggerEditor: Faster saves on series-heavy and PostgreSQL datasets through indexed raw-row updates, set-based orphan cleanup, true batched writes, duplicate-aware range updates, and a lightweight post-save refresh.
          - Logger import: Parsing and database writes now run without blocking QGIS, Cancel interrupts active database work, and legacy databases automatically receive a non-unique normalized timestamp lookup index before duplicate checking.
          - Security: Section plot TEM data (thickness/resistivity) is now parsed safely instead of with eval(), so a malformed or malicious database can no longer execute code when a TEM section is drawn; bad values raise a clear error instead.

          - LoggerEditor: Duplicate timestamps (two rows for the same obsid and instant, found in older databases) no longer crash Save. The editor warns, leaves both rows untouched, and still saves all other edits.
          - LoggerEditor: New duplicate-resolution workflow. A banner appears when the loaded obsid has duplicate timestamps, and a red marker along the plot bottom shows the periods where duplicates remain (it shrinks as you clean them). The "Resolve duplicates…" dialog (non-modal, floats above the editor) bulk-removes redundant copies (keeping the higher datetime precision), lets you keep one source per period for overlapping logger series, and points you to the plot to compare same-source value conflicts. Resolution is scoped to the From/To period, so different periods can keep different sources; a "Whole dataset" button widens the scope. All changes are undoable and written on Save.
          - LoggerEditor: Now starts clean — no observation point is loaded until you select one from the obsid list.
          - LoggerEditor: Fixed source-separated plot lines so rows sharing a source (including no source) draw as a single line instead of several identically-labelled lines.
